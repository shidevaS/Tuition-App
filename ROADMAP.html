The idea, in one breath

School subjects taught well and a real innovation track — coding, prompt engineering, AI tools, app-building, security basics — served as both live interactive classes (hosted by Shivani & Devendra) and on-demand integrated content. Growth is measured not just by marks but by a living profile: challenges done, skills earned, a portfolio that proves what you can build.

PILLAR · 01

Two pillars, one roof

A Subjects pillar (grades 6–12, boards) and an Innovation pillar (coding → DSA, prompt engg, AI tools, ML, app-building, cyber basics) share the same student, the same XP, the same profile.

PILLAR · 02

Live & on-demand, blended

Every topic exists twice: as a live class on the calendar scheduled and as integrated material in the library. Miss the live class — the recording lands back in the roadmap, in context, the same night.

PILLAR · 03

Challenges build the habit

A compact daily task keeps the streak alive; a weekly challenge earns a badge; a monthly capstone gets featured. XP, levels and a visible skill tree make progress something students want, not something they're told to want.

PILLAR · 04

A profile that earns its keep

Not a vanity page. A shareable portfolio of projects & prompts, a skill tree, a progress dashboard, and certificates you unlock only by doing the work. The leaderboard rewards the people who actually levelled up.

Feature modules

Twelve modules make the whole product. Phase 1 ships identity & shell; Phase 6 ships parity & a real launch batch. In between, every module below is built to completion, not to a demo.

01 · Auth & roles

Student vs Admin/Host. Email OTP + Google. Seeded admins: Shivani, Devendra. Role-gated routes from day one.

02 · Home / dashboard

Today's class, today's challenge, streak & XP up top, continue-learning and "what's next." The screen students open daily.

03 · Roadmaps & content

Subject roadmaps per grade + Innovation roadmaps. Modules → lessons → resources (video, notes, quizzes, curated links). Admins author; students complete; progress tracks.

04 · Live classes LIVE

Jitsi embedded in-app, JWT-secured rooms. Calendar, "join live", auto-attendance from participant events, live chat/Q&A, polls. Recording auto-archives into the library.

05 · Challenge engine

Daily (quiz / problem / prompt), weekly (submission + admin review), monthly (capstone, leaderboard, featured). XP, streaks, badges, skill points toward the skill tree.

06 · Profile & portfolio

Public showcase (pinned projects, prompts, write-ups), skill tree, progress charts, certificates, rank. The artifact a student carries out of a year here.

07 · Leaderboard & forum

Weekly / monthly / all-time boards, batch cochorts. Per-topic discussion & peer Q&A — answers can themselves earn small XP.

08 · Certificates

Auto-issued on module / roadmap / challenge completion. Verifiable via a shareable link — the sort a parent or employer can trust.

09 · Notifications

Class reminders, challenge deadlines, results, announcements. In-app + email now; FCM push on mobile in Phase 6.

10 · Admin console

Shivani & Devendra's cockpit: schedule & host live classes, author content, set & grade challenges, manage batches, read engagement analytics.

11 · Mobile companion

React Native (Expo), same API. Offline content downloads, push, attend live from a phone. Shares logic with web via a shared TS client.

12 · Payments & tier later

Razorpay for paid tracks/tiers, once a free batch is actually learning. Optional — the product works fully free-first.

P1.Foundation

Foundation & access

Monorepo, deploy pipeline, auth, roles and a real brand shell — so the whole product has a skeleton to grow on.

  • Monorepo: web (Next.js App Router, TS, Tailwind, shadcn) + mobile (Expo) + shared TS client & types.
  • Postgres + Prisma schema, Redis, S3-compatible storage, env & Docker.
  • Email-OTP + Google auth; Student / Admin roles; seeded admins Shivani & Devendra.
  • Design system: the palette & type, base components, role-gated layouts.
  • Landing page: brand, the two pillars, "join a live class" CTA. Deployed to a URL.
Exit

A user registers/logs in, sees a role-correct shell, admins see the console, and the live URL works.

P2.Content

Roadmaps & content library

The substance: structured learning a student can actually move through, and an authoring path for admins.

  • Data model: Pillar → Roadmap → Module → Lesson → Resource.
  • Seed Subject roadmaps (grades 6–12, core subjects) + Innovation roadmaps (coding, prompt engg, AI tools, ML, app-building, cyber basics).
  • Library + lesson view: video, notes, quiz, curated external link — all in roadmap context.
  • Admin authoring: build roadmaps, attach resources, reorder.
  • Progress: lesson-completed, roadmap %, "continue learning".
Exit

A student completes a roadmap end-to-end and sees progress; an admin authors a module without touching code.

P3.Live

Live classes (Jitsi)

The core of the brand: Shivani & Devendra teaching, live, to real students — fully integrated, not a pasted link.

  • Self-hosted Jitsi, JWT-secured rooms named per class; embed via iframe with controlled entry.
  • Admin scheduling: create a class, link it to a roadmap/subject, set time & batch.
  • "Join live" from web & mobile; attendance auto-captured from participant events.
  • Live chat / Q&A / polls over WebSockets; hand-raise queue.
  • Recording archived automatically → listed back in the library post-class; replay.
Exit

Shivani or Devendra hosts one real live class; students join from either platform; attendance & recording are saved untouched.

P4.Challenges

Challenges & gamification

The hook that turns "a course" into "a daily practice." Growth should feel like progress, not homework.

  • Daily engine: one small task/day (subject quiz, coding problem, prompt task) — keeps the streak.
  • Weekly challenge: coding / prompt-engg / worksheet with submission + admin review.
  • Monthly capstone: build a mini app or solve a research-backed problem; leaderboard + featured showcase.
  • XP, levels, badges, streaks, skill points feeding the skill tree.
Exit

A full 30-day rhythm runs — daily → weekly → monthly — with XP, badges and a live leaderboard.

P5.Profile

Profile, portfolio & community

Make the student's growth visible — to them, to peers, and to whoever they show it to next.

  • Public portfolio: pinned projects, prompts, write-ups; shareable URL & auto-certificates.
  • Skill tree + progress dashboard (XP over time, mastery, completion %).
  • Leaderboard (weekly / monthly / all-time) + batch cohort ranking.
  • Per-topic discussion & peer Q&A — helpful answers earn small XP.
Exit

A student has a shareable profile & portfolio; admins can feature work; the community is alive and answering each other.

P6.Launch

Polish, mobile parity & launch

Make it shippable to a real batch — offline, pushed, hardened, and measurable.

  • React Native parity: offline content downloads, FCM push, attend live from mobile; web PWA.
  • Notifications live (FCM + email): class reminders, deadlines, results, announcements.
  • Hardening: rate limits, backups, security review, student-data privacy.
  • Admin analytics dashboard: signups, engagement, completion, churn.
  • Soft-launch a real batch; collect feedback; payments tier (Razorpay) only if monetised.
Exit

A real (free or paying) batch runs end-to-end, stably, with Shivani & Devendra operating it daily.

How we start small

One cohort, two admins, free first. The loop that has to close before anything else matters: a student opens the app → sees today's lesson and challenge → attends the live class → earns XP → next day it's waiting for them again. Close that loop in Phases 1–4 with real content. Profile, community, parity and scale follow only once the loop holds.

Payments, a marketing site and "big launch" scale are explicitly deferred to Phase 6 — they're a reward for a product that already retains a batch, not a fix for one that doesn't.
